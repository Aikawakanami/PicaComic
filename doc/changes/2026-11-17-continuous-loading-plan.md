# 连续加载失败处理与来源/ID去重（待实施）

- 状态：方案已纳入个人仓库 `dev` 的知识库，按用户要求暂缓实施。
- 日期：2026-11-17（Asia/Shanghai）。
- 范围：通用连续浏览列表；不借此改分页选择、阅读或下载队列。
- 本次交付范围为方案文档。手动跳过范围、无新增阈值等建议细节留待实施前确认。

## 1. 背景与目标

连续模式加载失败不能默默跳过失败页；按漫画源稳定标识和漫画 ID 去除重复条目，同时避免一直失败或重复响应造成无限请求。已加载内容及多选集合应保留。

## 2. 问题与当前依据

【已实现：静态依据】`lib/components/comics_list.dart → ComicsPageLogic.loadNextPage` 调用 `getComics(current + 1)`，在 `Res.error` 后仍执行 `current++`，成功后直接 `comics.addAll(res.data)`，没有列表身份去重。触发点位于 `ComicsPage.build` 最后一个网格条目的构建，底部错误尚无持久重试区域。

`lib/network/base_comic.dart → BaseComic.id` 提供 ID，`ComicsPage.sourceKey` 提供来源；`Res` 当前主要用 `errorMessage` 表达错误，未统一携带可可靠区分登录、限流、解析失败等原因的结构化类型。`lib/network/app_dio.dart → AppHttpAdapter.fetch` 对部分异常已有有限重试，不能再在列表层叠加无限重试。

【推演／待核实】特定页返回内容异常、解析失败或服务端分页缓存异常时，可能该页失败而后一页成功；断网、登录失效或限流则可能所有后续页都失败。没有对真实站点执行破坏性增删或人为制造服务端异常。

## 3. 源加载能力边界

【已实现：静态依据】`JmNetwork.searchNew` 等入口可以按页码独立构造请求。`lib/comic_source/built_in/ehentai.dart → _EhentaiGalleriesLoader.call / loadNext` 则使用缓存和网页下一页链接，缺少中间结果时请求更大的 UI 页号仍会尝试同一个失败链接。

【建议】“允许跳过失败页”应由具体加载入口声明，未知入口默认不支持；不能只凭 UI 接口有整数页号，就假定可以独立跳页，也不能将整个 EH 源的所有入口一概归类。

## 4. 建议方案

1. 失败暂停自动加载，不推进请求页号/游标，不修改已加载列表、去重集合或多选集合。用异常收尾释放 loading 状态，刷新代次使旧请求失效。
2. 底部持续显示失败页及“重试本页”；手动重试同一请求，不清空列表或回到第一页。首版不在列表层增加持续自动重试，尊重网络层已有有限重试。
3. 已确认支持独立页码的入口可提供“跳过本页继续”，只在用户点击后跳过一页，并明确记录/展示缺页；不能伪装为该页加载成功。后一页仍失败则再次暂停，不连续自动跳页。链式/未知入口不提供该功能。
4. 首批和后续批次都按 `(sourceKey, comic.id)` 去重，保留首次出现的条目与顺序，不按标题、页号或卡片位置判断。空/不稳定 ID 需保守处理，不能把所有空 ID 合并成一条。集合与当前结果会话同生命周期，刷新/换源/改变查询等一并重置。
5. 成功但全部重复，仍是成功请求，应推进后续加载位置，不能当作失败或已到底。加载触发不能仅依赖“新增的最后一张卡片”，否则无新增时可能停住。
6. 【建议阈值】连续 3 批成功却没有新条目时暂停自动加载，显示“暂无新内容，可继续加载”，让用户手动继续；不将其直接记为永久终点。原始空响应、全部被过滤、全部重复与明确无下一页需要分别处理。
7. 只有源明确返回无下一页、可靠总页数达到末页等条件才确定结束；去重不能补回远端增删/重排导致的漏项。选择继续使用原有来源+ID元数据副本，不因列表去重而丢失。

## 5. 待实施计划

- 定义成功/失败/暂停/结束状态、请求位置与显式跳过记录。
- 明确各入口的独立跳页能力，未知或链式入口保守处理。
- 实现首批/追加去重及底部失败/无新增交互，不改用真实账户作为默认回归数据。
- 补回归、同步知识库，获后续实施授权后再构建或更新真机。

## 6. 验收建议

- 连续失败不会自动推进、重复弹提示或无限触发；已有内容仍可浏览、多选和收藏。
- 重试仍请求原页，成功后只追加唯一新条目；异常也能释放加载状态。
- 支持跳页的入口经用户操作可跳过坏页并加载后一页；链式入口不误显示可跳过。
- 同页/跨批重复去除，不同来源的同 ID 保留，首次出现顺序稳定。
- 全重复批次可继续，达到无新增阈值后暂停并可手动恢复，不误判永久结束。
- 刷新/查询变化不接纳旧响应或沿用旧去重集合，已有多选不会被追加去重误清除。
