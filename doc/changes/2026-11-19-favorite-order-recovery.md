# 本地收藏新增位置与旧收藏顺序恢复

## 问题与原因

无指标排序时，`lib/foundation/favorite_query.dart → FavoriteQuery.snapshot` 按 `display_order` 从小到大显示。`lib/foundation/local_favorites.dart → _insertComic` 在新收藏放最前时用小于当前最小值的位置。`onReadEnd` 会覆盖 `time`，该字段已经用于最后阅读时间。

【已验证：执行证据】原始导出与真机当前收藏库包含相同的 10 个原收藏夹，共对应 25,233 条旧收藏。当前旧记录的相对次序与上次恢复后的快照一致。与原始导出相比，8 个夹的旧项完全反序，另外 2 个夹也有顺序差异。157 条恢复后新增的收藏位于各自夹的旧项之前。用原始导出的 `(收藏夹, type, target)` 判定旧记录，可避开最后阅读时间被更新的问题。

## 方案与兼容

- 【已实现：静态依据】`lib/base.dart → Appdata.settings[53]` 新配置的默认值为「最前」。现有已保存的添加位置仍由各自配置决定。
- 【已实现：静态依据】`lib/foundation/local_favorites.dart → folderToJsonString / loadFolderData / readData` 以明确的显示位置导出单夹 JSON，按文件数组顺序导入单夹及旧版 JSON。整包 SQLite 恢复在 `lib/foundation/import_database.dart → _mergeFavorites` 继续保留源库内部位置顺序。
- 【已验证：执行证据】针对本机数据，首次备份后以原始导出及恢复快照交叉比对。在停机快照的副本上，按原导出顺序为旧项重分配旧项占用的位置。事务验证新项完整行和位置、原有主键集合、收藏的阅读时间、数据库结构和收藏夹设置一致，并通过 SQLite 完整性检查。

本机已混排的收藏采用一次性校正。已知顺序来自原始导出，应用启动时没有按日期阈值自动重排。
