# 大数据包导入卡顿与中断恢复

- 级别：Level 1
- 状态：已实现并完成本轮真机验证与数据恢复
- 授权依据：用户反馈将原应用导出的用户数据导入多选测试版时失败、白屏或长时间无响应，随后确认可以重新打开。

## 1. 背景与目标

保留原应用、导出文件和当前测试版数据，修复大批量 SQLite 数据导入的卡顿，并恢复中断时留下的历史暂存库。个人备份只用于本次明确请求的本机诊断与恢复，不进入仓库或测试夹具。

## 2. 需求与验收

- AC-01：约 2.5 万条收藏、7 千条历史的导入在后台合并，界面事件循环仍可响应，不逐条发起封面下载或 WebDAV 同步。
- AC-02：保留已有记录，收藏按 `(target,type)` 去重；重复导入不增加重复记录；单库写入失败回滚并保留待合并文件。
- AC-03：启动自动恢复 `history_temp.db` 中的历史与图片收藏；兼容缺少 `max_page` 或图片收藏表的旧历史库。
- AC-04：导入错误返回失败、释放等待窗口并可重试；先解包校验，再改变现有服务或文件；设置与标签落盘后才报告成功。
- AC-05：保留用户原导出和修复前备份，更新正常入口 APK 后核对恢复结果。

## 3. 现有实现分析

【已实现：静态依据】修复前 `LocalFavoritesManager.readData` 对每条收藏调用 `addComic`，逐条保存/刷新并发起封面缓存；`HistoryManager.tryUpdateDb` 对每条历史调用 `addHistory`，每次重建全量缓存并触发保存。`Appdata.writeData(false)` 内仍默认调用带同步的 `updateSettings()`；`importData` 仅捕获解包阶段异常，部分后处理异常会留下等待窗口。启动不恢复 `history_temp.db`。

【已验证：执行证据】本机诊断确认收藏主键集合与导出一致，历史与图片收藏仍留在暂存库；采集时未发现目标应用的原生崩溃，用户确认可重新打开。以上支持导入阻塞/未完成的判断，但没有复现用户当时的全部白屏过程。共享文档不记录个人条目、账户、源状态或凭据。

## 4. 技术方案

新增 `lib/foundation/import_database.dart → mergeFavoriteDatabases / mergeHistoryDatabases`，在隔离线程内用预编译 SQL 和事务合并，每库一次提交，已有主键跳过。导入完成只刷新一次缓存/UI，不预下载整库封面；源暂存库仅在成功后删除。`HistoryManager.init` 恢复未完成历史，失败保留暂存文件并记日志。

`lib/tools/io_tools.dart → importDataFromFile` 使用独立暂存目录，先验证 appdata 和收藏/历史数据库，再复制及合并；显式路径的旧 WebDAV 版本整包跳过。仅在实际替换 Cookie/下载数据时关闭对应服务，并在 finally 尝试恢复及清理本次暂存目录。手工导入保留本机下载路径/认证开关；设置、屏蔽词和收藏标签等待落盘。`importDataSetting` 在 finally 关闭等待窗口。

## 6. 验证结果

【已验证：执行证据】当前 Android 14 真机 4 组测试全部通过：启动恢复历史/图片收藏，大库及重复导入/设置落盘，事务故障回滚，非法包失败后服务可用并成功重试。25,231 条收藏的完整手工导入约 533 ms，10 ms 定时回调执行 50 次；该数据量下事件循环持续响应。多选原有 8 项回归也全部通过。本机日志为 `E:\Program Files\AndroidDev\logs\data-import-device-test.log`、`multi-select-after-import-fix.log`。

测试入口为 `integration_test/data_import_test.dart`，必须使用独立 `.devtest.importcheck` 包，不能将测试目标安装到已有个人数据的多选测试版。夹具生成 25,231 条收藏、7,028 条历史和 6 条图片收藏；没有真实账户或站点请求。静态检查新增模块和测试通过；其余修复文件无 error/warning，存在既有弃用 API 等 info。

更新前发现多选测试包被 Flutter 测试工具按旧缓存包名误卸载；工具源码已核对，用户确认没有手动卸载。已从事前完整快照还原，随后使用修复版的正常 UI 重新选择用户指定数据包，观察到“成功导入”。再次冷启动进入应用；收藏、历史、图片收藏的主键集合与原导出逐条一致，各库 quick_check 为 ok，设置只有按原规则保留的本机下载路径与导出不同。原版应用保留、原导出 SHA-256 未变，启动日志未见初始化失败或未处理异常。完整快照及核对记录仅留在本机 E 盘 `AndroidDev/recovery/2026-11-16-import`，未进入仓库。中性验证应用和临时恢复副本经用户明确授权后已清理，完整备份继续保留。恢复过程与预防方式见[开发指南](../development.md#大库导入恢复检查)。测试夹具运行在独立包，但不能据此声称设备上的其他测试包未被工具收尾影响。
